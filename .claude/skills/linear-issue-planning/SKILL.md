# Linear Issue Planning

## Purpose
Convert a Linear issue into a concrete implementation plan that is small, testable, and PR-friendly.

## When to use
Use this workflow when:
- starting a new issue
- refining backlog work
- translating acceptance criteria into technical steps

## Workflow
1. Read the issue from Linear
2. Extract:
   - goal
   - scope
   - acceptance criteria
   - dependencies
3. Inspect relevant code only
4. Produce:
   - implementation plan
   - test plan
   - possible risks
   - out-of-scope notes

## Rules
- Keep issue scope small
- Each plan step should be verifiable
- Map technical steps to acceptance criteria
- Avoid implementation during planning unless asked

## Output format
- Issue summary
- Acceptance criteria
- Relevant files
- Implementation plan
- Test plan
- Risks
