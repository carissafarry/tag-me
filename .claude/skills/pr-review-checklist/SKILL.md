# PR Review Checklist

## Purpose
Ensure each pull request is easy to review, linked to the correct issue, and production-minded.

## Checklist
- PR title starts with the Linear issue ID
- Scope matches one issue only
- Acceptance criteria coverage is explicit
- Tests are included or gaps are explained
- No unrelated refactors
- Risks and follow-ups are listed
- Branch naming follows convention

## Review output format
- Scope check
- Acceptance criteria coverage
- Test coverage
- Risks
- Suggested reviewer focus
